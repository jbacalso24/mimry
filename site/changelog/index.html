0.8.0

21 Oct 2026 Latest

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade. The first query after upgrading reparses every indexed file, and the upgrade then refreshes the installed skills and hooks.
  • mimry install --refresh adds Claude Code's PowerShell tool to the search hook, so mimry queries run there are tagged with their session (#556). mimry doctor reports a hook table from 0.7.0 as incomplete and prints the repair command.
  • Installing from a uv throwaway env (uvx mimry install) now stops before writing anything when the mimry on PATH is another version, and says how to upgrade it (#545). Hooks used to run the older copy and fail.
  • The session command log keeps a keyed hash of each query, so a short secret typed as a query cannot be guessed from the file (#546). Rows written by 0.7.0 are ignored.

New features

  • An opt-in prompt hook names the files to read first for each prompt in Claude Code: mimry install --hooks --prompt-hook (#516). Session feedback is now recorded when the agent stops, not only after the next command.
  • MCP queries are tagged with their session through the PreToolUse hook, so session learning covers agents that use the MCP tools (#518).
  • Read commands work in a sandbox that cannot write MIMRY's cache: they answer from the index that exists and say once that it cannot be updated, with the folder to point MIMRY_CACHE_HOME at (#527, #549, #557). A cache inside the project is no longer indexed as part of the project.

Fixes

  • Redaction catches more secrets: in comments, URLs, f-strings and subscript assignments (#512), in tuple assignments and auth headers inside strings (#528), and in chained and one-element assignments, split string literals and Authorization values with any scheme (#553).
  • A multi-line secret is redacted line by line, so the file keeps its shape and is still indexed, and a docstring that mentions a password keeps its prose (#536).
  • Secret scans, the prompt hook and feedback redaction run in time proportional to the input on worst-case text, such as long runs of escaped quotes or dotted names (#529, #537, #551).
  • The search hook stays quiet on pipes, word regexes and searches of named files (#517).
  • Session learning keeps the session's last query through Stop, matches queries exactly, and counts edits made in the same clock tick as Stop on Windows (#531, #534). A query that starts with a secret label keeps its session tag (#556).
  • mimry install registers its own mimry-mcp rather than the first one on PATH, keeps --prompt-hook in repair hints, and prints tidier output (#508, #532, #510).
  • MIMRY's own installed skill files are no longer indexed (#507).
  • A brief file error on a busy Windows machine is reported as itself, not as a missing index pointer (#538).

Other changes

  • An accessibility statement, and issue forms for a file MIMRY missed and for feature requests (#552).

0.7.0

21 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade. The first query after upgrading (find, preflight and the like) reparses every indexed file, and the upgrade then refreshes the installed skills and hooks.
  • mimry install --refresh rewrites the installed skills, and adds the new hook entries to a project that already has MIMRY's hooks. In Claude Code those are an outline for a large file that the agent reads whole, and a restore of the working set after a context compaction.
  • Embeddings are optional and off until you install them: uv tool install "mimry[embed]", then mimry embed download, which fetches a 64 MB model once.
  • A code file with secret-looking lines is now indexed with those lines redacted, instead of being left out (#470). Files that are not code, sensitive-named files, and code that cannot be redacted cleanly are still left out.

New features

  • A long find query, of 20 or more distinct words, also matches on meaning when the optional embedding model is installed (#488).
  • Session learning records the files read and edited after a find as feedback (#486). MIMRY_SESSION_FEEDBACK=0 turns it off.
  • In Claude Code, the files the agent was working on are restored after a context compaction (#487).
  • mimry stats shows the tokens MIMRY saved, estimated, for this session and all time (#489).
  • In Claude Code, a large file that the agent reads whole is outlined instead (#484).
  • A learned reranker orders the top 50 results (#468).
  • Files that define the identifiers a task names are lifted in the ranking (#467), and a keyword ranking of files is fused into find for long queries (#472). Both change the order of results, and the ranking is more accurate.

Fixes

  • Redaction no longer reads a == comparison as a secret assignment, keeps the quotes, escapes and brackets of a redacted value, and keeps := intact (#474, #485, #498). A quoted value that a line break splits is redacted line by line, more comparison and => forms are caught, and redacted code stays parseable (#502).
  • The search hook is quiet on a search of a single file, and it is capped per session (#480).
  • A tsconfig whose extends bases share a base reads that shared base once, so indexing does not repeat the work (#466).
  • An unreadable embedding title cache is rebuilt, and embed status, status and doctor report a broken model (#496). A broken embedding model is skipped instead of being loaded on every search (#502). Recording session feedback no longer makes a finished command wait for a busy index, and keeps the files the agent opened meanwhile (#496).
  • The README and site figures match the benchmarks, and the line-range saving is described first (#481, #482).

0.6.2

18 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade. The first command after upgrading reparses every file, so MSBuild, plist and XAML files and the Groovy fixes show up without a full reindex.
  • mimry path --json lists each other candidate in ambiguous once, as {label, path, line}, instead of a list of paths (#435).

New features

  • .csproj, .fsproj, .vbproj, .props, .targets, .plist, .xaml, .resx and .nuspec files are read as XML: MSBuild properties and targets, plist keys and XAML names are symbols, and a ProjectReference links to its project (#436).
  • A tsconfig.json that extends a base such as tsconfig.base.json resolves the base's path aliases, as in Nx and other monorepos (#446).

Fixes

  • A malformed JSON file nested very deeply no longer stops mimry index, a JSON file with a byte order mark and comments keeps its keys, and tsconfig.json with comments no longer shows a parse error (#432).
  • UTF-16 source files such as plists, project files, Python and Markdown parse, a byte order mark no longer hides a Markdown heading on the first line, and SVG icons without text are no longer listed as empty documents (#444, #451).
  • A Groovy class right after a wildcard import is found again, methods with nested generic bounds such as <T extends Comparable<T>> are indexed, and import static a.b.C.* links to the class file while import a.b.C.* links to the package, or to the class file when a.b.C is a class (#433, #445, #451).
  • A Groovy line with many generic types no longer makes indexing hang (#445).
  • Feedback records the files a task changed as missed when its context pack suggested nothing, and a folder passed as --context is not taken for a pack (#434, #447).
  • mimry path prefers a name with the exact case, names the symbol and line it used, and says when no path exists within 6 steps (#435, #447).
  • A small .map file is no longer treated as a minified bundle (#435).
  • After an upgrade, index says which files it reparsed instead of "No file contents changed", and feedback stats says "No commits yet." in a new repository (#447).
  • The README gives the data file symbol limit as 256 KiB, the site shows the current mimry path output, and the README says how to install without uv and which folders are always skipped (#436, #448, #451).

0.6.1

17 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade. The first command after upgrading reparses every file, so Groovy files, Haskell class methods and Helm template keys show up without a full reindex.
  • mimry path prints the path as a chain, each relation between the two nodes it joins; and --json adds an ambiguous field when a name matches several symbols (#417).
  • A data file with a syntax error ({"a": 1,) now counts as "could not be parsed" and keeps no keys, like broken code; JSON with comments and trailing commas, as editor settings allow, still reads fine (#420).

New features

  • MIMRY parses 41 languages: Groovy and Gradle join, with classes, methods, Spock feature methods, Gradle tasks, imports that link to the exact file, and call and inheritance edges (#406, #415, #422).
  • Haskell class method signatures and defaults are symbols, and Haskell and Fortran module imports link to the exact file (#401, #403, #416).
  • index, preflight and status -v say which documents are searchable by name only (damaged, encrypted, empty, compressed too much) and which were cut at a cap (#400, #420).
  • A query that is a file's name ranks that file first, and find says when a file named in the query is not indexed (#404, #418).
  • mimry path says when a name matched several symbols and which one it used (#417).

Fixes

  • Minified bundles found by their content no longer crowd out source files, while hand-written files with long lines keep their ranking (#405, #419).
  • A file name's extension alone no longer counts as a name match, so find "session.ts" stops listing every .ts file (#418).
  • Helm templates keep their keys after the first template action (#402).
  • YAML nested too deeply to read gets its own warning instead of "Fix the syntax" (#420).
  • Size limits print as 20 MiB, status -v lines its document lists up, --language scope lines show the display name, and find -v no longer repeats config evidence (#421).

Benchmarks

  • The token benchmark README records a trained embedding model for --semantic: it located fewer tasks in every mode, so --semantic keeps its hashed vectors (#423).

0.6.0

17 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade; it refreshes the skills, always-on rules and hooks you installed. The first command after upgrading reparses every file, so the new languages and whole-document search take effect, and index says how many unchanged files it reparsed (#397).
  • .html, .css and .scss files no longer take the boost source files get for edit tasks (#365).
  • .pp files are Pascal and .m files Objective-C only when their content says so; Puppet and MATLAB files become searchable text (#396).
  • A JS/TS const holding a function or arrow is now kind function (or component with JSX), and calls inside a local's initializer count for the enclosing function (#360).
  • Fortran and Pascal program blocks are kind program, not module (#397).

New features

  • MIMRY parses 40 languages, up from 21: Elixir, Haskell, OCaml, R, Julia, Solidity, Fortran, Pascal, CSS, SCSS, HTML, Vue, Svelte, YAML, JSON, TOML, XML, Terraform and SQL (#355, #357, #363, #366, #372). Data files give their keys as dotted names, Kubernetes documents give Deployment/web, Terraform blocks keep their reference names and kinds, and secret values are never indexed (#392).
  • PDF, Word, Excel and PowerPoint files are searched in full, and a result names the page, section, sheet or slide to read (#367, #390).
  • mimry install covers Windsurf, Cline, Roo Code, Zed, JetBrains Junie and Grok Build (#369, #395).
  • A Docker image, ghcr.io/jbacalso24/mimry, for amd64 and arm64 with the grammars baked in (#371).
  • mimry preflight --semantic and mimry_preflight(semantic=true) add semantic matches to the ranking; it stays opt-in, since it located the same tasks on the token benchmark (#375, #376).
  • --language accepts the names users see, such as Terraform, TypeScript or Objective-C (#397).

Fixes

  • A YAML file nested past 200 levels no longer crashes index; it is reported as unparsed and stays searchable (#391).
  • The secret scan runs in linear time over long runs of spaces; a deeply indented file indexed in 40 seconds now takes under 2 (#394).
  • A cache folder MIMRY refuses to write to gets one plain error from every command and MCP tool (#373).
  • uninstall keeps a skill file another installed platform still uses, Zed with a commented settings.json says to paste the entry by hand, and uninstall with nothing installed prints only that (#395, #397).
  • callers and callees rows say line 4 instead of a bare :4 (#397).
  • llms.txt lists all 9 default MCP tools (#389).

Other changes

  • The README and site lead with what MIMRY gets you (#368).
  • The adapter modules live in one adapters package, and CI runs the tests in parallel (#354, #358, #359, #362).

0.5.0

17 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade; it refreshes the skills, always-on rules and hooks you installed. The first command after upgrading rebuilds the index, and it now indexes source files the secret scanner used to skip by mistake.
  • Install and init now add only .mimry/ to ignore files, and init removes the mimry-out/ line older versions added (#316, #351).
  • mimry_why and mimry_explain return fields instead of CLI text, so MCP clients that read their stdout should read the fields (#348).
  • The post-commit hook records feedback for the last context pack only when the commit is about that task (#340).

New features

  • mimry history searches commit messages and changed files, preflight names the commits behind a removed or renamed path, and the mimry_history MCP tool does the same (#315, #347).
  • Suggested checks come from Makefile and justfile targets, tox and nox sessions, CI workflow steps and the scripts they run; nested packages run from their own folder with their own package manager, and checks guessed from tool names appear only when the project names none (#313, #323, #350).
  • find matches Chinese, Japanese and Korean words in content and file names (#322).
  • callers, callees and impact pick one of two same-named symbols with --line N or --file path:N (#319).
  • Preflight, the context pack, route and explain list the files to edit first, and tests first only when the task is about tests (#317).
  • explain ranks its key symbols by the task and shows how they connect (#320, #352).
  • Plan commands accept the plan name shown in plan list (#349).

Fixes

  • The secret scanner no longer skips source files over a JSON array, a typeof check or a short number under a credential-looking name, and status -v names the files it skips (#337).
  • route matches role words whole, so "helper" no longer routes to docs or "latest" to QA (#338).
  • The grep hook answers with a symbol only when the whole pattern names it (#339).
  • impact leaves local variables out of its targets and credits their calls to the enclosing function (#342).
  • doctor reports a missing grammar cache folder the same way index does, without a reinstall hint (#343).
  • bench passes over release and bump commits that start with an emoji, and pre-commit-only changes (#318, #346).
  • install --status keeps --no-mcp in its repair hint, --file misses name the file and suggest close paths, and a failed why lookup prints only the miss (#349).
  • Help for every option, mimry update --help, local times in status -v and the pack, and readable small size limits (#321, #351).

Other changes

  • The README walks through one task before and after (#314).
  • The AUR build fetches and verifies the sdist once (#311), and the CI job limit is 45 minutes (#345).

0.4.1

16 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade; it refreshes the skills, always-on rules and hooks you installed. The first command after upgrading rebuilds the index, so imports resolve more precisely and the lines to read first are recomputed.
  • Commands now exit 1 when they find nothing and 2 on a blank task or query, instead of 0 (#298). Scripts that treated any non-zero exit as an error should allow exit 1 for find, related and semantic.
  • mimry_impact is now one of the default MCP tools (#300).

Fixes

  • Every query command indexes or builds the graph first when it is missing, instead of answering from nothing (#295).
  • Output piped to an agent or a file is UTF-8 on every platform (#296).
  • A Python standard-library import no longer links to a same-named module inside a package, and TypeScript from '.' and from '..' imports resolve to the folder's index file (#297).
  • A missing name or file, or a search with no matches, exits 1; a blank task or query exits 2 and writes nothing; MCP marks real failures with isError, and path no longer guesses for a file that is not indexed (#298).
  • The hook finds names that start with an underscore, stays quiet for globs like **/*.py, and never answers with a Markdown heading or SQL table (#299).
  • The installed skill names only MCP tools the server lists, install --status respects --no-mcp, and uninstall removes only what MIMRY created and says what it did; uninstall --git-ignore removes MIMRY's global ignore lines (#300).
  • Suggested verification commands come only from the project's own manifests, never from install snippets in README files (#303).
  • Files over the 1 MB limit are counted and named, grammar failures show their real cause, and status totals stay right after a rename (#304).
  • impact --changed includes the tests that reach a changed file when the changed function has no callers (#305).
  • Feedback notes redact AWS, GitHub and Slack tokens and private key headers without a key= label (#306).
  • The lines to read first cover the function that holds the code, instead of a stray piece next to it (#308).

Other changes

  • The MIMRY logo in the README, on the website and as the social preview (#307).

0.3.3

14 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • Upgrade with mimry upgrade. The first command after upgrading rebuilds the index, and the rebuild keeps nothing from the old one, so text the new privacy rules redact is gone from the cache (#206).
  • Run mimry install --platform <name> again to add .mimry/ to Git's global ignore file (#213). After that, mimry init no longer edits each repo's .gitignore. --no-global-gitignore skips it.
  • The privacy rules are stricter, so a few files may drop out of the index (#204). .conf, .properties, .tfvars, Dockerfile and other text formats MIMRY doesn't parse are now checked for credentials, and *.env files are skipped by name. Files whose only "secret" was a URL-valued setting such as TOKEN_URL are indexed again.

New features

  • mimry callers and mimry callees show who calls a function and what it calls (#163).
  • MIMRY parses Bash, PowerShell, Lua, Perl (#157), Dart, Objective-C and Zig (#166).
  • mimry install adds .mimry/ and mimry-out/ to Git's global ignore file, once per machine (#213).
  • The site has a changelog page (#158), and the site and README show contributors (#159).

Fixes

  • Commands run from a subfolder of an indexed repo answer from the repo's index, and create no .mimry/ there (#212).
  • A repo under a non-ASCII path works; --root pointing at a file or a drive root fails with one line; find on a repo that was never indexed indexes it first; why says when a path is missing or outside the repo (#212).
  • Credentials in the middle of a sentence are redacted, in queries as well as in files (#204). A placeholder after a credential label is no longer treated as a secret (#165).
  • Calls resolve by scope, through package re-exports, and within Swift, Kotlin and C# modules (#208).
  • Go, Rust and PHP imports link files (#201), and absolute Python imports resolve in src/ layout projects (#164).
  • Zig function bodies, Rust Type::method() calls and Objective-C .h headers are recorded (#207).
  • Python files that start with a BOM, subclasses of Base[T], and files with a syntax error keep their symbols; index and status name the files that could not be parsed (#211).
  • Indexing a minified JavaScript bundle takes seconds, not minutes (#211).
  • mimry symbol <file.py> matches the file name (#187, thanks @wzd8888).
  • A case-only rename is picked up, and --file accepts either slash (#210).
  • The MCP server stays up when a tool is asked about a folder that isn't set up, and rejects an invalid outcome with a clear error (#203).
  • install never overwrites a settings file it can't parse, an MCP config it can't write is a warning, and install-only warnings no longer mark a repo unhealthy in doctor (#205).
  • MIMRY says when tree-sitter grammars can't be downloaded, and tries only once (#155).
  • A copied .mimry folder is explained the same way in every command (#160).
  • The AUR build waits for the new sdist on PyPI (#154).

0.3.1

13 Oct 2026

  • Release notes on GitHub
  • PyPI

Upgrade notes

  • The MCP server now lists 8 core tools by default (#125); set MIMRY_MCP_TOOLS=all to get every tool, or a comma-separated list.
  • mimry install --status now exits 0, 1 or 2 (#128) and reports a skill written by an older MIMRY as out of date (#140). After upgrading, run mimry install --platform <name> again (with the same --project, --always-on, --hooks flags) to refresh the skill.
  • On Windows, close the agents that use MIMRY before upgrading. Their running MCP servers lock MIMRY's files and the upgrade stops halfway. uv tool install --force mimry repairs a failed upgrade (#139).

New features

  • Agent hooks now refresh the index when a session starts and after each edit (#127).
  • find, symbol, related and semantic reindex first when files changed, the same as preflight, in the CLI and MCP. When git reports the same working tree as the last index, the check is skipped, so an unchanged repository answers without walking the tree (#98).
  • mimry find is scoped to the current directory inside an indexed repository. Use --everywhere or an explicit --path-glob to search outside that directory (#92).
  • mimry doctor reports the install source, the running MCP servers and the agent registrations (#126).
  • mimry install supports Cursor and GitHub Copilot in VS Code (#122, #124).
  • MIMRY records feedback from each commit automatically (#119).
  • mimry feedback stats shows usage and ranking quality (#121).
  • Each task now gets its own context pack (#116).
  • Choose which files to index with a mimry.toml, and map file extensions to languages in it (#104, #109).
  • The search hook names mimry find on broad searches, so agents know to use it (#106).
  • A new git worktree is set up on its first lookup, with its own index (#101).
  • Results tell agents which lines of each match to read first (#27).
  • Search can return short source snippets in the CLI and MCP, on request (#23).
  • Search can filter by language and path, and pages of results stay stable across requests (#24).
  • Add mimry doctor, which checks the installation, parsers and index and says how to fix what it finds, without changing anything (#25).
  • mimry preflight shows elapsed time while it works (#96).
  • When an agent connects to the MCP server, it is told when to use MIMRY, and the server reports its version (#29).

Fixes

  • The MCP server answers its first request in about 0.1 seconds, instead of 2 to 6 seconds while a large library loads at startup (#113).
  • Keep MIMRY running on an incomplete install, and say how to repair it (#19).
  • A skill written by an older MIMRY is now reported as out of date, not up to date (#140).
  • Nested Git worktrees are excluded from their parent's index, so their files are not duplicated, and a folder named worktrees is no longer mistaken for a linked worktree (#105, #117).
  • Untracked files that .gitignore names are no longer indexed (#30).
  • An index from another cache location is explained instead of crashing, and preflight rebuilds it (#28).
  • An index from an older MIMRY is rebuilt automatically (#88).
  • Feedback keeps the leading dot in file paths (#120).
  • Every graph match gets a content score before results are cut to the limit (#26).
  • Installing the skill on Windows waits out file locks instead of failing (#81).
  • The global skill installs under the directory named by CODEX_HOME (#76).
  • Installs use the MCP library version that CI tests, and the next major version cannot arrive untested (#77).

0.1.0

7 Sep 2026

  • Release notes on GitHub
  • PyPI

Determinism

  • Add the narrow mimry plan recursive decomposer: deterministic leaf-only splits, canonical repo-local JSON storage, terminal/JSON/Markdown projections, structural validation, semantic SHA-256, deterministic inventory, and read-only MCP parity. It stores explicit tree structure only and does not execute, schedule, refine, or track work.
  • Establish an explicit determinism contract splitting canonical semantic state (file/symbol/edge/community/chunk identities, parser facts, ranking and tie-breaking, context-pack evidence ordering) from the operational envelope (timestamps, generation UUIDs, absolute paths, mtimes, feedback event IDs, SQLite byte layout). Documented in docs/determinism.md.
  • Derive canonical IDs from the schema version and the repository-relative path instead of the absolute checkout path. Two clones of the same repository at different locations now produce identical file, symbol, edge, community, and semantic-chunk identities. Semantic chunk_id no longer carries the machine-local root UUID either.
  • Refuse index generations built under the old path-dependent identity scheme (GENERATION_SCHEMA_VERSION 1-3) with an actionable rebuild message, rather than partially reusing identities nothing else in the build produces.
  • Sort filesystem traversal and every persisted collection by a single normalization rule (canonical_rel_path: POSIX separators, NFC, case preserved, codepoint-ordered and therefore locale-independent), and reject same-root native paths that collide after NFC normalization before publication.
  • Reject duplicate node, symbol, and edge IDs whose records conflict, instead of resolving them by last write. Records identical in every field are deduplicated under a documented policy.
  • Give edges a total order over every canonical field and a documented EXTRACTED-over-INFERRED conflict rule, applied at every graph assembly site rather than only inside build_graph.
  • Give symbol resolution a total, documented selection order (kind priority, relative path, line start, line end, symbol ID). Genuinely ambiguous inheritance and import targets are still declined rather than resolved by picking the first candidate.
  • Add deterministic secondary ordering before every SQL cutoff. A tied BM25 rank no longer lets physical row order decide which rows survive LIMIT, and semantic chunk reads are ordered so explanation previews and reason labels are stable.
  • Acquire each file through bounded matching reads, derive its hash, size, mtime, and parser input from that snapshot, then verify post-acquisition freshness after adapters finish. A file changed mid-index is marked unindexable; mixed-version evidence is never persisted.
  • Add mimry digest, which hashes normalized semantic state rather than raw SQLite bytes or the generation manifest.
  • Add a real end-to-end determinism gate over a frozen multi-language fixture (scripts/determinism_matrix.py) covering scanner, Python/TS/Java/PHP/Go/SQL/Markdown parsing, graph and communities, SQLite/FTS, local semantic retrieval, and context-pack generation, across creation order, checkout root, PYTHONHASHSEED, clean-cache repeats, and locale/timezone. CI runs it on Linux, macOS, and Windows and a dedicated job compares every platform's digest against a committed golden value.
  • Convert the __main__ self-checks in the graph core into committed pytest tests.

Graph engine

  • Replace the external graph dependency with MIMRY's own graph engine in src/mimry/core/. Indexing parses each file once and derives defines, imports, and calls edges from what it already read, instead of copying the tree to a temporary directory and re-parsing it in a subprocess.
  • Resolve import statements and call sites to real files and symbols. MIMRY previously collected import strings but never resolved them, so its graph had no file-to-file edges at all. Unresolvable or ambiguous references are dropped rather than guessed.
  • Extend language coverage to Go, Rust, and C# alongside Python, JavaScript, TypeScript, JSX, and TSX, at no new dependency cost.
  • Rank by following relationships, not only by matching text: query relevance now propagates two hops along edges.
  • Stop demoting full-text evidence whenever the graph has an opinion. A content-only result was previously multiplied by 0.75 if the graph returned anything, and a file found by both signals had its content score discarded; corroborating evidence now adds.
  • Measured against the recorded baselines on nine cases: ndcg@5 0.6300 -> 0.6907, recall@5 0.8542 -> 0.8958, primary-hit@3 0.5000 -> 0.7500, decoy rate 0.1351 -> 0.1081, and time to a queryable indexed graph roughly halved.
  • Rename public graph terminology for the native engine: --skip-graph, mimry status, the MCP skip_graph argument, and the status payload key graph are canonical. A compatibility window keeps --skip-graphify, mimry graphify status, MCP skip_graphify, and the graphify status key functional for existing clients. The graph engine identifier is mimry-core.

Cross-platform

  • Fix Windows portability defects in home-directory sandboxing (including APPDATA, LOCALAPPDATA, and XDG_DATA_HOME isolation), descriptor syncing, timestamp identity checks, capability-guarded file operations, and cp1252-safe CLI output. UTF-8 artifacts preserve original Unicode.
  • Test Windows, Linux, and macOS across Python 3.11-3.13 in the committed CI matrix.

Packaging and support floor

  • Restrict source distributions to reviewed source, tests, documentation, and license files; exclude vendored, generated, cache, build, and local-work bulk.
  • Add artifact contract tests and Windows/Linux/macOS CI for Python 3.11, 3.12, and 3.13; the unlocked sdist lane invokes only extracted artifact source/scripts.
  • Package determinism_aggregate.py, support standards-valid XLSX inline strings, reject empty explicit edge IDs, and fail closed on unknown future generation schemas while preserving the old-schema upgrade classification.
  • Pin the proven tree-sitter-language-pack 1.12.2 compatibility floor after 1.13.5 broke TSX symbol extraction, and test unlocked extracted artifacts in CI.
  • Define 0.1.x as an internal checkout/direct-wheel release rather than claiming compatibility with PyPI-style indexes.
